### Issues Fixed

#### 1. ✅ Pydantic ValidationError: `google_application_credentials` Extra Field Not Permitted

**Problem:**
```
pydantic_core._pydantic_core.ValidationError: 1 validation error for Settings
google_application_credentials
  Extra inputs are not permitted [type=extra_forbidden, input_value='.gcp/service-account-key.json', input_type=str]
```

**Root Cause:**
- Pydantic v2 uses a different configuration approach
- The `Config` class was not properly set to ignore extra fields from the `.env` file
- Environment variable `GOOGLE_APPLICATION_CREDENTIALS` was present in `.env` but not defined in the Settings model

**Fix Applied:**
- Updated `backend/api/config.py` to use Pydantic v2's `ConfigDict` with `extra="ignore"` setting
- Changed from nested `Config` class to `model_config = ConfigDict(...)`
- This allows the Settings model to ignore undefined environment variables

**File Changed:**
- `backend/api/config.py`

**Code Change:**
```python
from pydantic_settings import BaseSettings
from pydantic import ConfigDict  # Added this import

class Settings(BaseSettings):
    # ... fields ...
    
    model_config = ConfigDict(
        env_file=".env",
        case_sensitive=False,
        extra="ignore"  # Ignore extra fields from .env
    )
```

#### 3. ✅ Chat History Maintenance

**Status:** Already working correctly

**Verified Components:**
- ✅ Database schema has proper `chat_sessions` and `chat_messages` tables
- ✅ `db_helper.py` has proper functions for session management:
  - `create_chat_session()` - Creates new sessions
  - `get_or_create_session()` - Gets existing or creates new
  - `save_chat_message()` - Saves messages and updates session
  - `get_patient_chat_sessions()` - Retrieves session history
  - `get_session_messages()` - Gets messages for a session
  - `delete_chat_session()` - Archives sessions
- ✅ `ChatHistorySidebar.jsx` properly loads and displays sessions
- ✅ Backend API endpoints in `chat_history_routes.py`:
  - `GET /api/chat/sessions` - List sessions
  - `GET /api/chat/session/{session_id}/messages` - Get messages
  - `DELETE /api/chat/session/{session_id}` - Delete session
  - `POST /api/chat/session/create` - Create new session

**Integration Flow:**
1. User sends message → `api/main.py` `/api/chat` endpoint
2. Session is created/retrieved via `db_helper.get_or_create_session()`
3. User message saved via `db_helper.save_chat_message()`
4. Agent processes and responds
5. Agent responses saved via `db_helper.save_chat_message()`
6. Frontend loads history via `ChatHistorySidebar` component
7. Chat history persists and is associated with the logged-in patient

### Database Schema

**chat_sessions table:**
```sql
CREATE TABLE IF NOT EXISTS chat_sessions (
    session_id TEXT PRIMARY KEY,
    patient_id TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_message_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    title TEXT,
    is_active INTEGER DEFAULT 1,
    FOREIGN KEY (patient_id) REFERENCES patients(patient_id)
)
```

**chat_messages table:**
```sql
CREATE TABLE IF NOT EXISTS chat_messages (
    message_id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    role TEXT NOT NULL,  -- 'user' or 'assistant' or 'system'
    content TEXT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    agent_name TEXT,
    needs_human_review INTEGER DEFAULT 0,
    FOREIGN KEY (session_id) REFERENCES chat_sessions(session_id)
)
```
